# 课表自动同步（kb-sync + 油猴脚本）

把广西师范大学教务系统的课表同步到 Obsidian，**只在课表发生变更时提醒**。

---

## 一、方案演进（为什么最终用油猴脚本）

最初的设想是「脚本抓取教务接口」。实测后发现两个**硬性阻断**，方案因此调整：

| 尝试 | 实测结果 | 结论 |
|---|---|---|
| 直接请求课表接口 | `303 → /jw/admin/login → sso.gxnu.edu.cn/cas/login` | 需要登录态 |
| 从 Edge 提取 Cookie | Cookie 前缀为 **`v20`**（非可解的 `v10/v11`） | 需新方案 |
| 解密 `v20` | 密钥前缀 `APPB`，**双层 DPAPI + 浏览器进程身份绑定**，离线解密失败 | ❌ 不可行 |
| 临时关闭 Edge 绕过文件锁 | 成功读取 21 条 gxnu Cookie，但值仍无法解密 | ❌ 不可行 |

`v20` 是 Chromium 127+ 引入的 **App-Bound Encryption**，其设计目的正是阻止脚本提取 Cookie。

**最终方案**：改由**浏览器自身**（油猴脚本）读取已登录的课表页并导出 JSON，
Python 脚本只负责解析、比对、写笔记。全程不触碰加密 Cookie，不注入进程，不提权。

```
Edge（已登录教务）
   ├─ 油猴脚本「GXNU 课表采集器」→ course-schedule-*.json
   └─ 或 Ctrl+S 另存为「单个文件(*.mhtml)」 → *.mhtml
                                        ↓
                     Edge 默认下载目录 ~/Downloads（不改路径）
                                        ↓
                    sync_course_schedule.py（解析 → 比对 → 写笔记）
                                        ↓
                     Obsidian Vault/课表/课表_2026-2027-1*.md
```

### 教务系统的两种课表页面（解析前提）

教务系统提供**两个**课表页面，结构完全不同：

**A. 旧版「我的课表」** —— **主页面 + iframe** 架构：

```
父页面  https://jwjx.gxnu.edu.cn/jw/admin?sfjrxk=1
          └─ 只有导航/标签栏，**不含课表表格**
  └─ iframe  /jw/admin//xsd/pkgl/xskb/queryKbForXsd
               └─ ✅ 课表表格在此（class="cell" / data-jcindex）
```

**实测证据**（2026-09-22）：
- 父页面 HTML 中 `data-jcindex` / `class="cell"` 出现次数 = **0**
- iframe 页面中 = **有**（表格 id="3"）
- 因此油猴脚本**不能**设 `@noframes`，且必须**跨同源 iframe 遍历**才能拿到表格。

v1.2.0 已实现 `collectDocuments()` 递归遍历同源 window 树，
自动跳过跨源帧，并带循环引用防护。

**B. 新版「课表查询」**（2026-10-05 新增支持）—— 单页应用：

```
https://jwjx.gxnu.edu.cn/jw/admin/api/getKbxx?xqid=3&userId=…&xnxq=2026-2027-1&role=xs
  └─ <table class="table">
     行 <tr name="rowkb" sid="<节次>">
     格 <td id="Cell<星期><节次>" rowspan="N" name="tdbox tdbox<星期>">
     内容 <p class="content-detail" title="课程名(教室)">
     周次列表 <p sid="6" class="active">第6周<span>10.05-10.11</span></p>
```

| 维度 | 旧版「我的课表」 | 新版「课表查询」 |
|---|---|---|
| 所在位置 | iframe 内 | 顶层单页（`/jw/admin/api/`） |
| 表格标志 | `class="cell"` / `data-jcindex` | `name="rowkb"` / `p.content-detail` |
| **周次范围** | **整学期一次给全**（单元格里写「4-9周」） | **一次只渲染一周**，需切换 tab |
| 空模板陷阱 | **有**（先给空骨架再 JS 填充） | 无（服务端直接渲染） |
| 采集方式 | DOM 穿透 → 同源直取 兜底 | 逐周 API 直取 / 点击 tab 遍历 |

> 两个页面**数据一致**（实测第 6 周 9/9 条完全对应），只是呈现方式不同。
> 脚本按 `name="rowkb"` 自动分辨，无需人工指定。

**C. 易班「易知独秀」课表**（`/yzdx/dean/course`，2026-10-10 新增支持）—— 第三个来源：

```
https://yiban.gxnu.edu.cn/yzdx/dean/course
  └─ Vue3 SPA；课表**不是 <table>**，是 Tailwind CSS Grid：
       <div class="grid grid-cols-8 grid-rows-12 …">
         格子用内联样式 grid-area: <起始节>/<星期+1>/<终止节+1>/<星期+2>
  └─ 数据来自同源接口 GET /api/v2/dean/course
```

接口返回 `{semester, current, weeks:[{weeks,beginDate,endDate}], course:{"<周次>":[…]}}`，
**一次给全学期**；单条课程含 `kcmc/xqj/qsj/zzj/jxddmc/skjsxm/…`。

| 维度 | 教务「课表查询」 | 易班「易知独秀」 |
|---|---|---|
| 课表载体 | `<table>` + `name="rowkb"` | Tailwind CSS Grid（无 `<table>`） |
| 教师名 | 单元格内 `span[title]` | **DOM 里没有**（只在详情弹窗） |
| 接口鉴权 | Cookie 即可 | **只认 `Authorization: Bearer`**，Cookie 不够 |

> ⚠ 易班接口不带 token 会返回 `{"code":401,"message":"登录超时"}`；token 在
> localStorage `__YZDX__USER_ACCESS_TOKEN__`。油猴脚本**不读该 token** ——
> 改为在 `document-start` 注钩子**捕获页面自身发出的那次响应**（见 v1.7.0 说明）。

三个来源在同步端**共用同一条解析路径**：易班数据被采集器转成与
`kbcxWeeks` 完全同构的 `yzdxWeeks`（见 `_structured_weeks()`），
故 `schedule_from_kbcx_weeks()` 直接复用，未新增解析器。

#### 支持的数据源格式（都从 Edge 默认下载目录只读获取）

| 格式 | 来源 | 说明 |
|---|---|---|
| `*.json`（含 UUID 名） | 油猴脚本 | 首选。**文件名常是 UUID**（见下），故按 `*.json` 宽匹配 |
| `*.mhtml` | Edge 另存为「单个文件」 | 自动定位 `queryKbForXsd` 分区 |
| `*.html` | Edge 另存为「网页，仅 HTML」 | 文件名需含课表关键词 |

> 采集器导出的 JSON 里，**结构化周数据**可能来自两种页面：
> `kbcxWeeks`（教务「课表查询」页）或 `yzdxWeeks`（易班「易知独秀」课表页）。
> 两者字段形状完全一致，由 `_structured_weeks()` 统一取出后走
> `schedule_from_kbcx_weeks()` 解析 —— **不依赖 `pageHtml` 的结构特征**
> （易班页连 `<table>` 都没有，任何基于表格的判据都会失效）。
> 易班导出因此没有 HTML 快照（`pageHtml` 允许为空），这是预期行为。

> ⚠ **为什么 JSON 用 `*.json` 而不是 `course-schedule-*.json`**：
> Tampermonkey 的 `GM_download` 走 blob URL 时，浏览器把文件存成**随机 UUID 名**
> （如 `56f6057b-52d3-4573-9c7d-5de4b79aa529.json`），脚本设定的文件名不生效。
> 实测（2026-09-23）因此**一直扫不到**采集导出。改为宽匹配后，
> 由内容校验（`collector == "gxnu-userscript"`）过滤无关 JSON，成本可忽略。

脚本会做**内容校验**：自动排除「学期暂未发布」之类的空壳导出与无关网页。

### ⚠ 空课表模板必须排除（2026-09-23 新增校验）

教务系统**先返回一张空的课表模板**（96 个空的 `<td class="cell">`），
课程内容随后由 JS 填充。因此「有 `class="cell"`」**不等于**「有课表内容」。

**判据**（`_has_schedule_content()` / `MIN_FILLED_CELLS = 3`）：
统计「非空课表单元格」数量 ——

| 样本 | 非空单元格 | 判定 |
|---|---|---|
| 空模板（采集失败的那份 JSON） | **0** | ❌ 无效 |
| 真课表（MHTML / PageMarkdown 导出） | **13** | ✅ 有效 |

注意哪些特征**不能**用作判据：`\d+周`（空模板的周次筛选器里也有）和
`data-jcIndex`（空模板的节次列上就有，且大小写在不同来源间不一致，
故校验时 `data-jcindex` / `data-jcIndex` 两种都接受）。

该校验同时作用于 `_is_valid_json_export` / `_is_valid_html` 与
`fetch_html()` 的写入前二次检查；抓到空模板会**明确报错**，而不是静默产出
0 条课表覆盖已有文件。

### ⚠ 表格重复导致条目翻倍（2026-09-23 修正）

采集器导出的 `pageHtml` 里课表表格可能出现**两份**：
`doc.body.innerHTML` 已含表格，脚本又追加了一遍 `table.outerHTML`
（实测 `<table>` = 2）。后果：每门课被解析 2 次，**16 条虚增为 35 条**，
并破坏连堂课合并（出现「周五 第1 / 第1-3 / 第2-3」三行）。

两道防线：

1. **采集端**（脚本 v1.5.1）：只在 body 不含已填充表格时才追加 outerHTML。
2. **解析端**（`_dedupe_entries()`）：按
   `(星期, 课程, 教师, 教室, 节次, 周次)` 完整指纹去重，在 `merge_entries()` 之前执行。
   指纹含节次与周次，故只剔除**完全相同**的重复项，不影响同一门课
   在不同周次/节次下的正常多条记录。

> 验证：修正后该 JSON 解析出 16 条，与 MHTML 真值 `key` 集合**完全一致**。

> 注：早期实验性的 `edge_cookie.py` / `collect_cookies.py`（Cookie 提取）
> 已确认在本机 Edge 版本下不可用，保留仅作技术记录，正常流程**不需要**它们。

## 三、安装（一次性）

### 步骤 1：装油猴脚本

1. 若未安装，先给 Edge 装 **Tampermonkey** 扩展（Edge 加载项商店搜 "Tampermonkey"）
2. 打开下面的安装链接，Tampermonkey 自动弹出安装页 → 点「安装」：

   https://raw.githubusercontent.com/yuyangu/userscripts/main/gxnu-course-collector.user.js

   （备选：Tampermonkey 面板 → 「添加新脚本」，从 [userscripts 仓库](https://github.com/yuyangu/userscripts) 复制脚本全文粘贴保存）

### 步骤 2：配置下载目录

浏览器下载的 JSON 需要被脚本找到。推荐直接放到 Obsidian 里：

```
C:\Users\<你的用户名>\Documents\Obsidian Vault\课表\_inbox\
```

两种做法（任选）：
- **改浏览器设置**：Edge 设置 → 下载 → 位置改为上述 `_inbox` 目录
- **保持默认**：让文件下到 `Downloads`，脚本也会扫描
  `~/Downloads/course-schedule/` 和 `~/Downloads/`，无需手动搬

### 步骤 3：首次采集

1. 在 Edge 打开教务系统：
   `https://jwjx.gxnu.edu.cn/jw/admin?sfjrxk=1` → 点左侧「我的课表」
   （课表在 iframe 里，v1.2.0 脚本会自动穿透读取，不会误报"不在课表页"）
2. 页面右下角出现「📚 课表采集器」面板 → 点「采集并导出课表」
3. 浏览器下载 `course-schedule-<时间戳>.json` 到默认下载目录
   （或直接 `Ctrl+S` 另存为「单个文件 (*.mhtml)」，脚本同样支持）

> ⚠ 旧接口 `sdpkkbList` 已返回「学期暂未发布」；若你另存的是**父页面**（只有导航壳），
> 同步脚本会自动识别为无效并跳过，不会误报 0 条课表。

### 步骤 4：首次同步

```bash
python sync_course_schedule.py
```

首次运行会**建立基线**（不算变更），写入下面两个文件（详见第四节之二）。

## 三之二、三个输出文件（不同视图，2026-09-28 起改为周视图网格）

| 文件 | 内容 | 结构 |
|---|---|---|
| `课表_<学期>_周视图.md` | **周视图网格**（仿手机课表 App） | 每周一张 **7 列 × 12 节** HTML 网格表；表头为「星期 + 日期」；连堂课纵向合并 |
| `课表_<学期>_月视图.md` | **月视图**（逐日） | 按日期逐条列出，含周末；无课日标注「无课」；换月起新小节 |
| `课表_<学期>.md` | **课程汇总视图** | `一、课程汇总`（课程/教师/星期/节次/时间/周次/教室）＋`二、实践环节`＋`附：节次时间表（XX校区）` |

> 渲染函数分别是 `render_by_week()` / `render_month()` / `render_summary()`，
> 统一由 `write_targets()` 写出（各自保留各自的 Meld Encrypt 加密行）。
>
> 旧文件名 `课表_<学期>_按周次.md` 会被自动迁移到 `.backup/`，
> 其加密行会**先被新文件继承**再归档（见 `_migrate_legacy_targets()`）。

实现要点（`render_week_table()`）：

| 要点 | 说明 |
|---|---|
| 整周只出现一次日期 | 在表头（`周一<br>09.28`），格子里不再重复 |
| 连堂课纵向合并 | 节次相邻 + 同课同教室 → `rowspan`；`p > lo` 的格子不输出 `<td>` |
| 午休 / 晚休 | 第 5 节后、第 9 节后插 `colspan=8` 分隔行 |
| 格子内三行 | `课程名` / `@教室` / `教师`（仿手机版面）；教室去「雁山」前缀并把「区」去掉 |
| 放不下的信息 | 表格下方 `<details>` 折叠「课程详情」，列完整教室与教师 |
| 样式 | 文件头部内联 `<style>`，用 Obsidian 的 CSS 变量，自动适配明暗主题 |

> ⚠ **改渲染格式后必须把 `RENDER_VERSION` +1**。否则课表条目没变 →
> 状态判定「无变更」→ 新格式永远不落地（这个坑本轮踩过两次）。
> 当前 `RENDER_VERSION = 4`。

## 四、日常使用

```bash
VENV=python
cd "<项目目录>"

$VENV sync_course_schedule.py                  # 完整同步（有变更才写文件）
$VENV sync_course_schedule.py --dry-run        # 只比对，不动文件
```

### 退出码

| 码 | 含义 | 自动化任务如何处理 |
|---|---|---|
| 0 | 无变更 / 首次建基线 | 静默 |
| 1 | **有变更**，已更新 | 表格汇报差异 |
| 2 | 未找到导出文件 | 提醒去采集 |
| 3 | 解析失败 | 报告页面结构可能变化 |
| 4 | 检测到手工内容，已中止 | 提示确认后可 `--force` |
| 5 | 加密行超过 3 行，已中止 | 提示人工确认 |
| 6 | **部分周次数据无法安全合并**（拿不到既有条目） | 提示先采一次全学期建立基线 |

## 六、安全边界（请审阅）

**油猴脚本的权限与行为**：

| 项目 | 说明 |
|---|---|
| `@match` | 仅 `jwjx.gxnu.edu.cn/jw/admin*`，不在其他站点运行 |
| 网络请求 | **零**。不使用 `fetch` / `XMLHttpRequest` / `WebSocket` |
| 数据流向 | 只通过浏览器下载写到本机默认下载目录，不经任何第三方 |
| 读取范围 | 仅教务页 DOM（含**同源**子 iframe）；不读其他标签页、不读任何 Cookie；跨源帧自动跳过 |
| 面板位置 | 只在**顶层窗口**显示一次，子 iframe 不重复注入 |
| 可读性 | 单文件、无压缩、无混淆，可逐行审阅 |

**导出文件含姓名**；学号不在页面 DOM 中，由本地 `config.json` 提供。
落盘位置由你控制；若放到网盘同步目录，请自行评估。

**Python 脚本**：只读导出文件，只写 `课表/` 目录，无任何网络访问。

## 七、变更判定口径

对每条排课记录生成稳定指纹：

```
星期 | 课程名 | 教师 | 节次 | 展开后的周次 | 教室
```

**任一字段变化即视为变更**，例如：
- 换师（俞春强 → 唐振军，本学期确实存在）
- 周次增删（如「数字电路第 15 周单独排课」这类异常排课）
- 教室或节次调整

不视为变更：抓取时间不同、页面顺序不同、同一课程的连堂课合并。

## 七之二、连堂课合并规则（2026-09-23 修正）

教务系统的表格单元格**不代表**课程的逻辑分块。实测：

```
Cell51  周五 第1节    rowspan=1  软件工程专业导读 陶小梅 4-9周  @雁山理二区2-202
Cell52  周五 第2-3节  rowspan=2  软件工程专业导读 陶小梅 4-8周  @雁山理二区2-202
```

同一门连堂课被拆成两格，周次还差 1 周。旧实现把「周次」纳入分组键，
两条因周次不同被判为两组，输出成「周五 1」「周五 2-3」两行。

**现在的合并规则（`merge_entries`）：**

1. 分组键 = `(星期, 课程, 教师, 教室)` —— **不含周次**
2. 组内按起始节次排序，**节次首尾相接**（`next.start == cur.end + 1`）才合并
3. 周次取**并集**，且仅当两组周次**相等或互为子集**时才合并
   （避免把「1-8周」和「9-16周」这种真正不同的安排粘在一起）

上例：`{4..8} ⊆ {4..9}` → 合并为「周五 第1-3节 4-9周」。

## 七之三、校区作息（2026-09-23 修正）

两校区作息不同，**必须按校区取值**（来源：《广西师范大学作息时间表》）：

| 节次 | 雁山 | 育才/王城 |
|---|---|---|
| 第 1 节 | 8:20-9:00 | 8:00-8:40 |
| 第 2 节 | 9:00-9:40 | 8:40-9:20 |
| 第 3 节 | 9:50-10:30 | 9:30-10:10 |
| 第 4 节 | 10:40-11:20 | 10:30-11:10 |
| 第 5 节 | 11:20-12:00 | 11:20-12:00 |
| 第 6 节 | 14:10-14:50 | 14:30-15:10 |
| 第 10 节 | 19:10-19:50 | 19:30-20:10 |

早期版本只写了育才/王城一套，导致雁山学生看到的每节课时间**全部偏早**
（如第 1 节误显示 8:00-8:40，实际应为 8:20-9:00）。

校区由教室名前缀（雁山/育才/王城）自动推断（`_detect_campus`），
缺省时回退到 `config.json` 的 `campus` 字段。文件末尾的
「附：节次时间表（XX校区）」会标明所用作息。

## 七之四、部分周次合并（2026-10-05 新增）

### 为什么需要

新版「课表查询」页（`api/getKbxx`）**一次只渲染一周**。用它导出的数据
`weeks` 只有一周（如 `[6]`）。若直接整体覆盖既有课表，**会丢掉其他 13 周**。

### 合并规则

`apply_partial_merge()` → `merge_partial_weeks()`：

```
本次数据的 touched_weeks = [6]
既有课表覆盖周次        = [4,5,6,7,…,17]
                          ↓
只替换第 6 周的安排，其余周次从旧条目裁剪后原样保留
```

判定条件：`既有周次 - 本次覆盖周次` 非空 → 触发合并。
若本次数据已覆盖既有全部周次（如油猴脚本取的 19 周全量）→ 不合并，整体替换。

控制台输出：

```
数据只覆盖第 6 周，已与既有课表合并（9 → 18 条，保留第 4、5、7…17 周）
```

### 三个配套机制

| 机制 | 函数 | 作用 |
|---|---|---|
| **周次碎片合并** | `coalesce_weeks()` | 新版按周给数据，同一门课会产生多条（`weeks=[6]`、`weeks=[7]`…）。与旧格式（一条写 `weeks=[5..15]`）比对时会报**虚假变更**，故按「同课同时同教师同教室」合并周次 |
| **教室校区前缀归一化** | `_norm_key_text()` | 同一间教室，旧页面写 `雁山学生探究性自主学习`、新页面写 `学生探究性自主学习`。比较时去掉 `\|` 后的校区前缀（key 第 6 段才是教室），否则同一门课被判「新增 + 移除」 |
| **全角/半角归一化** | `_norm_text()` | 旧页面写 `公共体育（1）-乒乓球`（全角），新页面写 `公共体育(1)-乒乓球`（半角）。归一化在 `CourseEntry.__post_init__` 与 `diff_schedules` 两处生效 |
| **state 存完整条目** | `entries_from_state()` | 合并需要既有条目。新 state 存 `entries`；**老 state 只有 `keys`**，但 key 格式 `星期\|课程\|教师\|节次\|周次\|教室` 本就含全部信息，可完整还原 |
| **跳过周次如实转达** | `skipped_weeks` / `empty_weeks` | 采集器报告哪些周没采到（`skippedWeeks`）或确认无课（`emptyWeeks`）。同步脚本会打印提示；**跳过周不参与合并**，其既有数据原样保留 |
| **显式覆盖周次** | `touchedWeeks` → `touched_weeks` | 采集器显式声明本次覆盖了哪些周（**含该周无课的情况**）。结构化周数据里的空周会被 `schedule_from_kbcx_weeks()` 跳过，只靠条目反推的话那些周不算"被覆盖" → 某门课**被取消**时旧条目会残留。显式声明后：覆盖到全部周 → 走整体替换 → 取消的课能正确消失 |

> ⚠ 首次使用新版单周来源前，建议先用油猴脚本采一次**全学期**建立基线；
> 否则拿不到既有条目时会中止（退出码 6）而非静默覆盖。

### 实测记录（2026-10-05）

油猴脚本 v1.6.0 首次在新版页面采集，**API 直取 19 周只回了 14 周**
（静默丢了第 1、2、3、18、19 周）。v1.6.1 起对缺失的周改用**点击补采**，
并把结果如实写入 `skippedWeeks`，不再静默丢数据。

补采后又暴露第二个问题：新版页面的**空周**（当周没课）表格里没有课程卡片，
被 `findTablesIn()` 的「课程数 ≥ 3」阈值判成"找不到表格" → 误报为采集失败。
该阈值本是给**旧版「空课表模板」**用的；新版由服务端直接渲染，不存在空模板问题。
v1.6.2 为新版引入独立判据 `findKbcxTableIn()`（只要表格有 `name="rowkb"` 行即算数），
空周与采集失败从此能正确区分。

同一次采集的 diff 从 **7 增 4 删**（含 1 项虚假变更）收敛到 **6 增 3 删**
（全部为真实变化：第 15 周数字电路 3→2 节、第 17 周高等数学 3→2 节、
第 9 周软件工程导读 3→1 节）。空周不产生任何条目，对数据零影响（已用
19 周含 5 空周的模拟数据验证：解析结果与 14 周版本逐条一致）。

## 八、已知局限

1. **解析基于课表页表格结构**。若教务改版（例如改为纯 JS 渲染），需调整
   `_parse_grid_table` / `_parse_list_style` / `_parse_kbcx_table`。
2. 校历第 1 周起始日硬编码为 `WEEK1_MONDAY = 2026-08-31`，新学期需更新。
3. 当前学期常量 `SEMESTER = "2026-2027-1"`，换学期需同步更新输出文件名。
4. **手工编辑保护**：若你手工改过 `课表_2026-2027-1_按周次.md`，
   脚本会检测到并中止（退出码 4）。这是防止你的笔记被覆盖的护栏。
   —— 这个机制源于一次真实事故：我曾在清理测试产物时误删备份目录，
   导致原课表被测试输出覆盖。现已加此护栏，且备份不再自动清理。
5. **Meld Encrypt 加密行会被保留，不算手工内容**：
   你把课表文件里的 `**姓名**：…**学号**：…**校区**：…` 那一行
   用 Meld Encrypt 加密成了 `🔐<密文>🔐`（保护隐私，防止随 Vault
   同步到网盘泄露）。脚本重写文件时会**把该加密行原样搬回头部原位**，
   并**按文件各自保留**（两文件密文不同，不互相串入）。
   加密行超过 3 行（`MAX_PROTECTED_LINES`）时视为范围异常，停止写入
   （退出码 5，状态 `blocked_encrypted`）。
6. 输出文件的版式会被 Obsidian 重新格式化（YAML 列表化、表格对齐），
   同步重写时会回到脚本生成的样式，随后 Obsidian 再次格式化。
   属外观抖动，不影响数据。
7. **周视图用 HTML `<table>` 而非 Markdown 表格** —— 因为 Markdown 表格
   无法表达 `rowspan`（连堂课跨行合并），也做不了单元格内多行排版。
   Obsidian 渲染 HTML 表格正常，但**在「源码模式」下看到的是标签**；
   阅读模式下才呈现为网格。若你偏好纯 Markdown，请告知，可退回列表式。
8. 周视图网格里**课程名 / 教师名过长会被截断**（`…`）。
   完整信息在表格下方的「课程详情」折叠块里。
